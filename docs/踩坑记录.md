# 踩坑与经验（重建，v0.37）

> 来源：本会话实测、`dev/` 探针、构建日志、报错原文。
> 标 **待验** 的是未复现/仅一次观察；标 **可疑** 的是推理但没证据。

## 一、训练与显存

1. **FLUX.3 Base 实测**：512 ≈ 5 s/步，640 ≈ 12 s/步，**768 必 OOM**（16G）。
2. **MOSS 内置 trainer**：384 + 不 offload 能跑（2 步 48 s）；512 直接 OOM。**kohya 才可行**：int8 ConvRot + `--blocks_to_swap 20` + 缓存 TE，512 ≈ 12.5 s/步。
3. `aimdo memory compile error`：九成是**显存没清**（上次模型/训练残留）；其次 `bucket_mode=true`、`checkpoint_depth=5`。修法：重启 ComfyUI + depth ≤3 + bucket false。
4. **必须 `--disable-pinned-memory`**，否则 `页面文件太小 (os error 1455)`；工作区无管理员权限改页面文件。
5. **训练必须壳托管 ComfyUI**。孤儿进程会出现「训练需要壳托管的 ComfyUI」；修法：`pid_listening_on` → `taskkill` → 轮询端口释放 → 再 `ensure_server`。`ensure_server` 会“认领”健康的外部服，必须校验 child 是否为空。
6. `SaveLoRA` 写到 `output/loras`，不是 `models/loras`；需要移动/改名。
7. `existing_lora` 续训时文件名不含 `_steps_` 会 `int()` 崩；要 try/except 归零。
8. 训练前重启清显存是默认选项，不勾容易翻车。

## 二、采样与模型

9. **MOSS 官方**：≥50 步、CFG 3（3–6）、shift 5、euler、SLG skip 22。之前默认 25 步/CFG2.5/er_sde 是错的。
10. **MOSS shift 已在模型配置**（`sampling_settings.shift=5.0`）。外挂 `ModelSamplingSD3 shift=5` **直接出噪点**（4/8 步都炸），已回退。
11. **SLG 可用**：`SkipLayerGuidanceDiT` + `single_layers=22`（强档 22,24,26），慢约 25%，暗部/布料明显更实。MOSS 支持 `single_block` patch，所以通用 SLG 节点能生效。
12. **Qwen 2.1 CFG=1 时负面词完全无效**（幼儿腿/短腿的根因）；默认已改 CFG 4.0 / 45 步。
13. **LoRA 绑架构**：FLUX 训的挂 MOSS = 加载成功但零生效；kohya 的 `lora_unet_*` key 能被 ComfyUI 正常映射（强度 0 vs 5 有 5.5 像素差）。
14. **模型大小是参数量，不是训练数据量**：MOSS DiT 5B ≈ 5GB(int8)，TE Qwen3.5-9B ≈ 9GB；数据不进权重。
15. **负面提示词写「不想要的东西」**，不是「不要 XX」；中文能喂但英文稳。MOSS 人像先验强，深夜仍可能补光（待验：更强负面+低 CFG 能压多少）。
16. JSON 提示词**不会**让 MOSS 更稳（同内容 2 seed 对比无明显差异）；真正吃 JSON 的是官方 Layout 格式（bbox）。
17. **Layout JSON 只对 MOSS**；Qwen 2.1 的 TE 没训过 bbox，喂 JSON 会更差（可疑：可再测一版 Qwen 对比）。
18. ComfyUI 的 `MOSSImageLayoutPrompt` 在 API 下 ARRAY 输入校验失败（`unhashable type: dict`）；自己按源码拼 `{"summary","items","bbox_coord_space":"abs_centralized","bbox_format":"yxyx"}` 直接喂文本编码器可行（实测「MOSS」标题+杯子落位）。
19. 同 seed、batch 2 的两张图**内容不同**（实测像素均差 37）。严格对照用 batch 1；1024×2 很慢（待验：具体耗时）。
20. MOSS-Imagine（INT8 5.2GB，HF 平均 10.9 MB/s）真实感优于 SFT；裸模型接近实拍窗光。

## 三、依赖与环境

21. **sd-scripts 依赖死结**：transformers 5.14/5.17 要 `huggingface_hub<2`，diffusers 0.40 要 ≥2 的 API；解法是内嵌 Python 装 `virtualenv`，建 venv 后写 `_embedded.pth` 指向内嵌 site-packages（否则 venv 看不到 torch）。
22. 内嵌 Python **没有 `venv` 模块**，`python -m venv` 直接失败；用 `virtualenv` 包。
23. sd-scripts `requirements.txt` 末尾有 `-e .`，直接 `pip install -r` 会报 `file:///D:/deepseek-files` 不是 Python 项目；要单独 `pip install -e <sd-scripts>` 且 `--no-deps` 控制升级。
24. 内嵌 Python **没有 tkinter**，交接系统 `main.py --status` 跑不了（要用系统 Python）。
25. ComfyUI v0.42.1 的 `diffusers` 与本机 hub 版本冲突；最终把 diffusers 降到能用组合，或隔离环境（以 kohya 为准）。
26. **PowerShell 改 `Cargo.toml` 用 JSON 模式会把 TOML 写坏**（`"version": "x"` 行），踩了两次；只认 `version = "x"`。

## 四、壳工程/UI

27. **冷启动卡死**根因：`server_status` 是同步命令，在主线程做健康探测（超时数秒），每 3 秒一次。改 async + `spawn_blocking` + `ensureReady()` 排队后解决（实测 3.1 s 可交互）。
28. 图库卡顿：几千张时每次全扫。按「输出目录 mtime + stars mtime」缓存内存+磁盘，命中 0.2 s；前端一次渲染 120 张、滚动追加。
29. 模态框 z-index 曾低于图库（训练弹窗看不见）；统一 85。
30. `libTrain` 按钮曾硬编码 `disabled`，JS 只在有选择时启用 → 弹窗打不开。
31. 结果列曾不滚动/卡片被压扁（117px vs 图片 311px）；修 grid 行约束 + `grid-auto-rows: max-content`。
32. 重复定义 `SIMPLE_RATIOS` 与 `RATIOS` 冲突 → 重命名。
33. 收藏只存 stars.json 时文件管理器看不到；改为 `output\_favorites` 硬链接镜像（删除时移除）。
34. 图库破图：Shisei 发布包缺 55 组正面机位（288 组仅 1133 张线稿）；必须按实际文件过滤，缺机位回退其它角度，288→280。
35. 姿势库点击对 MOSS（不支持参考图）要退化为「填描述」，否则会白加一个无效参考。
36. 排版框曾无四角缩放；已加 4 手柄（最小 3%），模板含电商主图/海报/左图右文/三分屏/四宫格。
37. 小助手分析图必须带图；无图时 `analyze` 返回「用户没有附参考图」。
38. 小助手工具步数上限 4；模型偶尔不返回 JSON → 直接当 final 文本兜底（待验：稳定性随 prompt 变化）。

## 五、流程与判断

39. **官方文档优先于社区传言**：MOSS「JSON 提示词更稳」实测不成立；官方真正支持的是 Layout JSON。
40. **每轮必须真机验证**（CDP）：shift 那次就是没先小样验证，直接出了噪点。
41. **README 曾停在 v0.7 很久**（补丁锚点没匹配上）；文档更新必须跟版本号一起改。
42. 构建版本号要同步 `tauri.conf.json`（JSON）与 `Cargo.toml`（TOML）两处。
43. 测试用 CDP + `dev/cdp.py`；`generate` 返回的 images 是对象（`.path`），`read_output_image` 要绝对路径。
44. CDP 测试期间杀进程会 `ConnectionClosed`，先停测试再重建。
45. 1024 分辨率下 MOSS + SLG + batch2 明显更慢；512–896 更跟手（待验：精确耗时表）。
